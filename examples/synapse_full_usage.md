# synapse_full.maxpat — usage

A comprehensive Max receiver for synapse OSC. Visualises every
category of message synapse emits, for all 14 channels at once.

If you just want a minimal "hello world", use
[`synapse_starter.maxpat`](synapse_starter.maxpat) instead — that's
shorter and easier to read.

## What's in the patch

```
[udpreceive 9000]   ← Max 8+ auto-parses incoming OSC bundles
   │
   ▼
[route /synapse]
   │
   ▼
[route cv cv_rate gate gate_event rms peak centroid onset spectrum block clap]
   │   │       │    │          │   │    │        │     │        │     │
   ▼   ▼       ▼    ▼          ▼   ▼    ▼        ▼     ▼        ▼     ▼
   per-channel routers (14 outlets each, /1 .. /14)
   │
   └→ widgets organised in five sections (top to bottom):
        ◆ AUDIO    — 14 RMS sliders + centroid number + onset bang
        ◆ CV       — 14 value flonums + rate flonums
        ◆ GATE     — 14 toggles + edge buttons
        ◆ SPECTRUM — channel selector + 32-bin multislider
        ◆ CLAP     — 512-bin multislider (only when --clap is on)
```

The status row at the top shows:
- `bundles received` — running count of OSC packets that arrived
  (every audio block produces one bundle)
- `block #` — synapse's monotonic block counter (incrementing means
  audio is flowing)

## Running it

1. **Start synapse** (in your repo):
   ```bash
   cd /path/to/synapse    # the repo dir, not the vault
   uv run synapse run --source mock:drums --no-clap \
       --gate "1,2" --cv "3-6"
   ```
   Synapse defaults to `127.0.0.1:9000` for OSC. The patch's
   `[udpreceive 9000]` matches.

2. **Open the patch in Max**:
   - File → Open → navigate to `examples/synapse_full.maxpat`
   - The patcher opens in edit mode. Lock it (`cmd-E` or click the
     lock icon at the bottom-left) to start receiving.

3. **What you should see** (within ~1 second):
   - `bundles received` ticks up rapidly (~70-90/s)
   - `block #` increments
   - **AUDIO row**: all 14 RMS sliders dance with the mock drums
     pattern; centroid numbers settle around the spectral content;
     onset bangs flash on hit transients (kick on ch1, snare on ch2).
   - **CV row**: ch3-6 flonums show smoothed values; the rest stay
     near 0 (channels in audio role still get DC mean, but it's tiny
     for AC content).
   - **GATE row**: ch1-2 toggles light up when the mock drums fire;
     edge bangs flash on rising/falling edges.
   - **SPECTRUM row**: pick a channel from the umenu (ch7-14 are
     audio in the example above) — its 32 log-spaced bins update
     at ~30Hz.
   - **CLAP row**: empty unless you removed `--no-clap`. CLAP fires
     ~once per second when on.

## Forwarding to Unreal (or anywhere)

Tap any of the per-channel router outlets (`rt-rms`, `rt-cv`, etc.)
and feed into a `[udpsend <unreal-host> <unreal-port>]`. For
example, to forward channel-1 RMS to Unreal at `192.168.1.10:7000`:

```
[rt-rms]  outlet 0 (ch1)
   │
   ▼
[prepend /unreal/ch1/rms]    ← reformat for Unreal's expected address
   │
   ▼
[udpsend 192.168.1.10 7000]
```

You can keep the existing display widgets attached too — Max
patches can fanout one outlet to multiple destinations.

## A note on `[oscparse]`

The patch **does not** use `[oscparse]`. In Max 8+, `[udpreceive]`
already parses incoming OSC bundles and emits each constituent
message with its address pattern, so the chain is just
`udpreceive → route /synapse → route <category> → ...`.

If you are on an older Max (≤ Max 7) and the messages don't reach
the `route` objects, insert `[oscparse]` between `udpreceive` and
`route /synapse`:

```
[udpreceive 9000]
   │
   ▼
[oscparse]
   │
   ▼
[route /synapse]
```

## If nothing shows up

1. Is synapse running? Check the terminal where you started it —
   should print:
   ```
   synapse · running
     source:  MockSource (14ch @ 48000Hz, block 512)
     ...
     osc:     127.0.0.1:9000 (bundles per audio block)
   ```
2. Is port 9000 already in use? Try a different port:
   ```bash
   uv run synapse run ... --osc-port 9001
   ```
   Then in the patch, double-click `[udpreceive 9000]` and change
   it to `udpreceive 9001`.
3. Is Max blocked by macOS firewall? System Settings → Network →
   Firewall → check Max is allowed. (Local UDP usually doesn't
   need this but worth checking.)
4. Run a parallel sanity-check listener — if the listener sees
   bundles but Max doesn't, the issue is on Max's side:
   ```bash
   # in the synapse repo:
   uv run python /tmp/synapse_osc_listener.py 9000 5
   ```

## Layout customisation

The patch is generated by `scripts/gen_synapse_max_patch.py`. To
restyle / re-layout / change the channel count, edit that script
and re-run it:

```bash
uv run python scripts/gen_synapse_max_patch.py > examples/synapse_full.maxpat
```

You can also edit the `.maxpat` JSON directly — it's plain JSON,
just verbose. For a cleaner / smaller starting point, copy-paste
sections from this patch into a new patcher and remove what you
don't need.
